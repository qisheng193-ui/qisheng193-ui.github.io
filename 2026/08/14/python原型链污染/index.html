Python 原型链污染

2026/8/14 web安全 Python 原型链污染 类污染 Flask CTF

基础知识

原型：

每个对象拥有一个原型对象(prototype)，对象以该原型为模板，从原型继承方法和属性

原型链：

原型对象可能拥有原型，从中继承方法和属性，一层一层、以此类推，这样的关系结构叫做原型链

键值对、字典、元组、模块

键值对："key":"value" 类似这个格式的，键后边对应着相应值，这是键值对

字典：d = {key1 : value1, key2 : value2 } d 是一个字典

元组：tup1 = () tup1是一个空元组

模块：Python模块是一个Python文件，以.py结尾，包含了Python对象定义和Python语句，模块能定义函数、类、变量，也能包含可执行的代码

原型链继承特性

python中每个对象通过__class__属性指向其所属类，类通过__base__属性指向父类。当访问对象属性时，若当前对象/类中未定义，会沿原型链向上查找

原理

python没有原型这一说，但其继承关系却和js类似，这就导致了相关漏洞的诞生

Python 中的原型链污染是指通过修改对象原型链中的属性，对程序的行为产生意外影响或利用漏洞进行攻击的一种技术。
在 Python中，对象的属性和方法可以通过原型链继承来获取。每个对象都有一个原型，原型上定义了对象可以访问的属性和方法。当对象访问属性或方法时，会先在自身查找，如果找不到就会去原型链上的上级对象中查找，原型链污染攻击的思路是通过修改对象原型链中的属性，使得程序在访问属性或方法时得到不符合预期的结果。常见的原型链污染攻击包括修改内置对象的原型、修改全局对象的原型等

Python是对类的属性值的污染，不能污染类的方法

继承链终点 object

object 无 __base__，继承链到此终止。

可以给 object 新增自定义属性，但不能修改内置魔术属性。

污染条件——递归合并函数

需要存在递归合并函数（如merge、update）且未对特殊属性过滤。

def set_all_attr(obj, data):
    for k, v in data.items():

逐行拆解逻辑

假设传入可控 json 字典：

{
    "__class__": {
        "__base__": {
            "cmd": "hack"
        }
    }
}

执行流程：

  1. 第一层循环 k="__class__", v={ "__base__": {"cmd":"hack"} }
  2. 判断：v 是 dict → 触发递归
  3. 递归进入内层字典，循环 k="__base__", v={"cmd":"hack"}
  4. v 依旧是 dict，继续递归
  5. 内层 k="cmd"，v 不再是字典 → setattr(obj, "cmd", "hack")

危险代码

merge() 的作用是将源对象的键值合并到目标对象；只有递归实现、未过滤魔术属性、setattr()函数

  • src：攻击者传入的字典（污染源）

  • dst：程序里正常对象 / 字典（被修改的目标）

函数目标：把 src 的所有键值合并到 dst，遇到字典就递归往里合并

def merge(src, dst):	
    # 遍历src当中每一组 键k:值v
    for k, v in src.items():  

        # hasattr(dst, '__getitem__')
        # 判断dst是不是【字典】
        # 字典支持 dst["key"] 取值，底层依靠__getitem__
        if hasattr(dst, '__getitem__'):	
            # dst是字典分支
            # 如果dst里面已经存在k，并且当前v也是字典 → 需要递归合并内部字典
            if dst.get(k) and type(v) == dict:	
                merge(v, dst.get(k))
            else:	
                # 直接赋值：dst[k] = vstatic_folder 
                dst[k] = v

        # 走到这里说明：dst【不是字典】，是普通类实例对象
        # 判断：dst对象身上有没有属性k，并且v是字典
        elif hasattr(dst, k) and type(v) == dict:	
            # 取出 dst.k 这个属性，递归合并
            merge(v, getattr(dst, k))	
        else:
            # 重点！漏洞触发点
            # 给对象dst动态新增/覆盖属性 k = v
            setattr(dst, k, v)

函数形参默认值替换

主要用到了函数的__defaults__和__kwdefaults__这两个内置属性

__dedaults__

func.__defaults__以元组的形式按从左到右的顺序收录了函数的位置或键值形参的默认值，

  • 只收录 positional-or-keyword（位置或关键字形参） 的默认值。

  • 不包含：纯位置参数、仅关键字参数、可变参数 *args``**kwargs。

从代码上看，效果如下：

def func_a(var_1, var_2 =2, var_3 = 3):
    pass

def func_b(var_1, /, var_2 =2, var_3 = 3):
    pass

def func_c(var_1, var_2 =2, *, var_3 = 3):
    pass

def func_d(var_1, /, var_2 =2, *, var_3 = 3):
    pass

print(func_a.__defaults__)
#(2, 3)
print(func_b.__defaults__)
#(2, 3)
print(func_c.__defaults__)
#(2,)
print(func_d.__defaults__)
#(2,)

通过替换该属性便能实现对函数位置或键值形参的默认值替换，但稍有问题的是该属性值要求为元组类型，而通常的如JSON等格式并没有元组这一数据类型设计概念，这就需要环境中有合适的解析输入的方式

利用

如果攻击链路能够抵达函数对象，就可以污染 __defaults__，修改参数默认值。

示例攻击场景：

def exec_cmd(cmd=""):
    return os.system(cmd)

污染目标：exec_cmd.__defaults__ = ("whoami",)

后续无参调用 exec_cmd()，cmd 自动等于 whoami，触发命令执行。

__kwdefauults__

__kwdefaults__ 为字典类型，存储函数中仅关键字参数（keyword-only） 的默认值，键为参数名称，值为对应默认值。

def func_a(var_1, var_2 =2, var_3 = 3):
    pass

def func_b(var_1, /, var_2 =2, var_3 = 3):
    pass

def func_c(var_1, var_2 =2, *, var_3 = 3):
    pass

def func_d(var_1, /, var_2 =2, *, var_3 = 3):
    pass

print(func_a.__kwdefaults__)
#None
print(func_b.__kwdefaults__)
#None
print(func_c.__kwdefaults__)
#{'var_3': 3}
print(func_d.__kwdefaults__)
#{'var_3': 3}

  • 形参列表中单独 * 是分界线，其后所有参数均为仅关键字参数；

  • *args 同样充当分界线，*args 后方参数也是仅关键字参数；

  • 仅关键字参数默认值保存至 __kwdefaults__（dict）；

  • 无 * / *args 分割，不存在 keyword-only 参数，__kwdefaults__ 为 None。

_got_first_request

用于判定某次请求是否为自Flask启动后第一次请求，是Flask.got_first_request函数的返回值。直接影响装饰器 @app.before_first_request 的执行逻辑。

粘一下源码

from flask import Flask,request
import json

app = Flask(__name__)

def merge(src, dst):
    # Recursive merge function
    for k, v in src.items():
        if hasattr(dst, '__getitem__'):
            if dst.get(k) and type(v) == dict:
                merge(v, dst.get(k))
            else:
                dst[k] = v
        elif hasattr(dst, k) and type(v) == dict:
            merge(v, getattr(dst, k))
        else:
            setattr(dst, k, v)

class cls():
    def __init__(self):
        pass

instance = cls()

flag = "Is flag here?"

@app.before_first_request
def init():
    global flag
    if hasattr(app, "special") and app.special == "U_Polluted_It":
        flag = open("flag", "rt").read()

@app.route('/',methods=['POST', 'GET'])
def index():
    if request.data:
        merge(json.loads(request.data), instance)
    global flag
    setattr(app, "special", "U_Polluted_It")
    return flag

app.run(host="0.0.0.0")

源码逻辑简述

当新请求到达：

  1. 判断 self._got_first_request
  2. 如果 _got_first_request == False
    • 执行所有 before_first_request 注册的回调函数
    • 将 _got_first_request 设置为 True
  3. 后续所有请求不再触发 before_first_request

通俗理解：

before_first_request 回调只会在首次请求运行一次，依靠 _got_first_request 开关控制。

payload

{
    "__init__":{
        "__globals__":{
            "app":{
                "_got_first_request":false
            }
        }
    }
}

下一次 HTTP 访问网站时，会再次触发 before_first_request 内注册的全部函数。

def _get_template_source(app, template_name):
    # 防御路径穿越关键校验
    if os.path.pardir in template_name or os.path.sep in template_name:
        raise NotFound("Template not found")
    loader = app.jinja_env.loader
    return loader.get_source(app.jinja_env, template_name)

    目的：防止攻击者传入 

    ../../etc/passwd

    这类路径实现目录穿越。

三、类污染攻击原理（核心）

攻击目标

打通类污染链路，获取 os.path 模块对象，执行赋值：

os.path.pardir = "random_text"

篡改之后校验逻辑变化

原始判断：

if ".." in template_name

等价于源码写法：

if os.path.pardir in template_name

修改后 os.path.pardir = "random_text"

此时代码判断变为：

if "random_text" in "../../flag"

表达式结果：False

✅ 路径穿越防护逻辑失效！

后续传入：

render_template("../../flag")

不再触发拦截，Flask 会尝试跨目录加载文件，实现任意文件读取。
